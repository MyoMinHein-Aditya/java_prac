## Theory
### 1. PreparedStatement Interface
`PreparedStatement` is a sub-interface of `Statement`. It represents a precompiled SQL statement.
Key advantages:
- Pre-compilation: The database compiles the SQL query template once, resulting in faster execution when executed multiple times.
- Parameterization: Uses `?` (placeholders) instead of concatenating strings. Values are set using setter methods (`setString()`, `setInt()`).
- SQL Injection Prevention: It automatically escapes characters, preventing malicious SQL injection attacks.

### 2. ResultSet Interface
`ResultSet` represents the database result set generated by executing a statement that queries the database (`executeQuery()`).
- A `ResultSet` cursor is initially positioned before the first row.
- The `next()` method moves the cursor to the next row and returns `false` when there are no more rows.
- Getter methods like `getInt()`, `getString()` retrieve column values from the current row.

## Source Code
### Important Code Sections in `App.java`:
- Connection Setup:
  ```java
  Class.forName("com.mysql.cj.jdbc.Driver");
  conn = DriverManager.getConnection(url, username, password);
  ```
- PreparedStatement for Insertion:
  ```java
  String insertQuery = "INSERT INTO users(name, email) VALUES(?, ?)";
  PreparedStatement ps = conn.prepareStatement(insertQuery);
  ps.setString(1, "Abhishek");
  ps.setString(2, "abhi@sample.com");
  ps.executeUpdate();
  ```
- PreparedStatement for Query and ResultSet:
  ```java
  String selectQuery = "SELECT * FROM users";
  PreparedStatement ps2 = conn.prepareStatement(selectQuery);
  ResultSet rs = ps2.executeQuery();
  while (rs.next()) {
      System.out.println("ID : " + rs.getInt("id"));
      System.out.println("Name : " + rs.getString("name"));
  }
  ```
- Closing Resources:
  Always closes `rs`, `ps`, `ps2`, and `conn` to prevent resource leaks.

## Common Errors and Solutions
1. `SQLException: Parameter index out of range (1 > number of parameters, which is 0)`
   - Cause: Mismatch between question marks `?` in SQL and the parameter index used in `setString()`.
   - Solution: Check that the query has the matching number of `?` placeholders.
2. `SQLException: Table 'mydb.users' doesn't exist`
   - Cause: Database or table was not created before running the program.
   - Solution: Run `schema.sql` in MySQL Workbench or CLI.
3. `NullPointerException` on `conn.prepareStatement(...)`
   - Cause: `conn` returned `null` because database connection failed.
   - Solution: Check username, password, and port in `getConnection()`.

## Viva Questions and Answers
1. **Why is `PreparedStatement` faster than `Statement`?**
   - Because the database engine compiles and parses the query plan once and caches it. Repeated executions only pass data parameters.
2. **How does `PreparedStatement` prevent SQL injection?**
   - It treats input parameters strictly as values rather than executable SQL code, properly escaping quotes and delimiters.
3. **What is the index of the first placeholder `?` in JDBC?**
   - The index starts at `1` (not `0`).
4. **What does `ResultSet.next()` return?**
   - It returns `true` if the cursor moved to a valid next row, and `false` if there are no more rows.
5. **Can you read columns by name or index in `ResultSet`?**
   - Yes, both options are supported: `rs.getString("name")` or `rs.getString(2)`. Reading by name is preferred for clarity.
